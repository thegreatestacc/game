# SpellGame — MVP 0.1

Настольное приложение на Go + Ebitengine: главное меню, редактор характеристик
и игровой экран с текущим профилем персонажа и инвентарём.
`SpellGame.exe` открывает лаунчер с проверкой обновлений из приватного GitHub.
**Первый запуск требует опубликованного релиза и токена доступа.**
Пошаговая настройка и выпуск версий: [LAUNCHER.md](LAUNCHER.md).
Техническое задание: [spellgame_mvp.md](spellgame_mvp.md).

## Запуск и сборка

Для разработки нужен Go 1.26 или новее. Ebitengine закреплён на v2.9.9.
Первое получение зависимостей требует интернета. Лаунчер проверяет GitHub перед
каждым запуском; сама запущенная игра работает локально.

```powershell
go mod tidy
go run ./cmd/game
```

Сборка Windows x64 с тестами:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-windows.ps1
```

Или вручную из корня проекта:

```powershell
go mod tidy
go test ./...
$env:GOOS = 'windows'
$env:GOARCH = 'amd64'
$env:CGO_ENABLED = '0'
go build -trimpath -ldflags="-H=windowsgui" -o dist/SpellGame-game.exe ./cmd/game
go build -trimpath -ldflags="-H=windowsgui" -o dist/SpellGame.exe ./cmd/launcher
```

Для кросс-компиляции предусмотрен `sh scripts/build-windows.sh`.
Кросс-компиляция не заменяет проверку на Windows.

После успешной сборки запускайте `dist/SpellGame.exe` двойным кликом.
Кнопка «Играть» проверит релиз, установит обновление и запустит игру.
Для прямого запуска игры при разработке используйте `dist/SpellGame-game.exe`.
Go и игровой движок на компьютере игрока не требуются. Шрифт и его лицензия
встроены через `go:embed`; PNG, если добавлен до сборки, также встроен.
Рабочая папка не влияет на загрузку ресурсов. При распространении сохраняйте
`FONT-LICENSE.txt`, который скрипт кладёт рядом с EXE (для работы игры файл не нужен).

## Управление

- «Персонаж» — профиль Арканиста, класс Маг, уровень 1.
- «Играть» — текущие имя, класс, уровень, девять характеристик и инвентарь
  на 12 ячеек. Значения учитывают правки в меню «Персонаж». При первом запуске
  инвентарь пуст; получение и использование предметов пока не реализованы.
  Слева отображается нарисованный маг по референсу `images/characters/img.png`:
  тёмный капюшон, борода, бронзовая броня и посох. Вращение состоит из восьми
  исходных ракурсов с непрерывной интерполяцией формы и текстур на каждом
  обновлении: 480 промежуточных шагов за полный оборот длительностью 8 секунд.
  Это интерполяция 2D-спрайтов, поэтому мелкие детали могут слегка меняться
  между ракурсами; полноценная 3D-модель пока не используется.
  Анимация обновляется игровым циклом, независимо от частоты отрисовки.
- «Назад» или Escape — главное меню.
- «Выход» или закрытие окна — завершение приложения.
- Кнопки активируются левой кнопкой мыши по нажатию.

Рядом с каждой из девяти характеристик есть кнопки «−» и «+»: один клик
изменяет значение на 1 (для процентов — на 1 процентный пункт).
Для HP и MP меняется максимум и на столько же текущее значение, с ограничением
от нуля до нового максимума. Минимум максимального HP — 1; остальные минимумы — 0.
Шанс критического удара ограничен 100%, скорость — 999%, целые характеристики — 9999.
Изменения сохраняются при возврате в меню, но сбрасываются после закрытия игры.

Окно можно масштабировать;
логическая область 1280×720 сохраняется. Игра использует 60 обновлений в секунду
и вертикальную синхронизацию; фактическая частота кадров зависит от дисплея.

## Исходники и ресурсы

- `cmd/game` — запуск и сообщение об ошибке Windows.
- `cmd/launcher`, `internal/launcher` — окно лаунчера и запуск проверенной игры.
- `internal/updater` — доступ к приватным GitHub Releases и проверка обновлений.
- `.github/workflows/release.yml` — сборка и публикация версии по Git-тегу.
- `internal/app` — цикл игры, единый снимок ввода, переключение экранов.
- `internal/animation` — сопоставление деталей спрайтов и непрерывная анимация поворота.
- `internal/screens` — главное меню, профиль, игровой экран с инвентарём и тесты переходов.
- `internal/ui` — кнопки, текст, панели и декоративный фон.
- `internal/domain` — модель персонажа, не зависит от движка.
- `internal/assets` — встроенный Go Regular с кириллицей и лицензией BSD.

Портрет и вращение используют встроенный `internal/assets/sprites/arcanist-turntable.png`
(4 столбца × 2 строки: фронт, 45°, правый бок, 135°, спина, 225°, левый бок, 315°).
Спрайты созданы встроенным imagegen; запрос сохранён в `images/characters/arcanist-prompt.txt`.
В меню «Персонаж» показывается первый кадр. Необязательный `internal/assets/sprites/character.png`
может переопределить статичный портрет. При отсутствии или повреждении спрайтов
используется процедурная заглушка. Ошибка обязательного шрифта возвращается
с пояснением и показывается в диалоге Windows.

Справочник движка: https://ebitengine.org/en/documents/2.9.html

## Проверка готовности

Зависимости загружены, `go.sum` создан. Сборка Windows x64 выполнена:
`dist/SpellGame.exe` (лаунчер) и `dist/SpellGame-game.exe` (игра).
Команда `go test ./...` проверяет навигацию, анимацию и механизм обновлений.
Отрисовка окна лаунчера проверена на Windows. Реальный приватный релиз пока
не проверен: подключение GitHub возвращает 404, требуется настройка из LAUNCHER.md.
Дополнительно проверьте на Windows:

1. Запуск EXE из другой рабочей папки без файлов ресурсов рядом.
2. Читаемость русских надписей и наличие всех девяти характеристик.
3. Переход в профиль, возврат кнопкой и Escape несколько раз подряд.
4. Удержание мыши не вызывает повторных действий.
5. Изменение размера окна не обрезает интерфейс.
6. Завершение кнопкой «Выход» и системной кнопкой закрытия окна.
7. «Играть» открывает текущий профиль и пустой инвентарь; «Назад» и Escape
   возвращают в главное меню. Правки характеристик видны на игровом экране.

Навигационный тест: `go test ./...` (для пакетов движка нужна графическая среда).
Доменная модель отдельно: `go test ./internal/domain`.
